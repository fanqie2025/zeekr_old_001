# 让 AI 助手带着用户抓出车辆标识

普通用户（不会装 mitmproxy、看不懂抓包工具）最省事的做法：把下面这段提示词整段粘给任意一个 AI 助手——豆包、DeepSeek、WorkBuddy、Kimi、ChatGPT 都行——然后照它说的做。

它的设计原则：**AI 只做向导和解析，不碰账号**。全程不需要用户把手机号、验证码、token 交给 AI。

---

## 一、给用户：怎么用

1. 安装好这个集成后，添加集成到第二步会要求填「车辆标识」。
2. 打开你常用的 AI 助手，把下面 **第二节那一整段（从「你现在是我的…」到结尾）** 复制进去发出去。
3. 按它一步步回话。中途它会让你抓包，抓完把结果粘贴/上传给它，它会告诉你那 44 个字符是什么。
4. 把字符填回 Home Assistant 的输入框。

如果 AI 说"我分析不了二进制文件"，那就用它给的脚本：把抓包文件（`.har` 或 `.jsonl`）丢给 `tools/extract_identifier.py`，把输出贴回给 AI 复核。

---

## 二、提示词（整段复制）

```text
你现在是我的「极氪 001 Home Assistant 集成」安装向导，任务只有一个：帮我拿到我这辆车的
x-vehicle-identifier 值。请严格按下面的规则来做。

【这是什么值】
- 极氪官方 App 请求 gric-zhf-api.geely.com（车控网关）时，请求头里带
  x-vehicle-identifier。App 只在内存里用原生库密钥现算这个值，手机上不存、服务器也不下发，
  所以谁都没法自动生成，只能从一次真实抓包里抄。
- 形态固定：44 个 base64 字符，一定以 = 结尾，例如
  GNxEVYPZ7RjM1IPT1vqgC84gsNerq13jzTPXgfEX5Gg=
- 抄一次永久有效，跟着车走、不跟账号；换手机、换账号都不用重抓。
- 填错不会装死：Home Assistant 会当场报 00A06 Decrypt X-VEHICLE-IDENTIFIER failed.

【你的安全红线】
- 绝不要我提供极氪账号密码、短信验证码、登录 token。你不需要它们，也不要帮我登录。
- 不要建议我把 App 退出登录：极氪同一个账号同一时间只认一处登录，退登/重登会把正在用这个
  账号的 Home Assistant 顶下线。我如果必须登录，宁可用备用账号（车辆分享出来的那个）。
- 只读操作：抓包、看请求头、复制字符串。不要让我改车、不要让我装来路不明的软件。

【分步流程，一次只问一个问题，等我回答再继续】
第 1 步：问我用的是什么手机（iPhone / 安卓），电脑是 Windows / macOS / Linux，还是想完全
        不用电脑。
第 2 步：按情况给一条路线，别一次给三条：
        - 有电脑（推荐）：用 mitmproxy 一键抓取脚本。给他这两条命令：
              pip install mitmproxy
              python tools/catch_identifier.py
          脚本会打印本机局域网 IP 和一个 8081 端口的状态页。然后按顺序告诉他：
            ① 手机连同一个 WiFi；
            ② 手机 WiFi 设置里把代理设成手动：服务器=那个 IP，端口=8080；
            ③ 手机浏览器打开 http://<IP>:8081 ，看到「等待中」说明代理已通；
            ④ 手机浏览器打开 http://<IP>:8080 装根证书，并且一定要去系统设置里信任它
              （iPhone：设置 → 通用 → 关于本机 → 证书信任设置）；
            ⑤ 打开极氪 App →「爱车」页面 → 下拉刷新一次；
            ⑥ 回到 http://<IP>:8081 刷新页面，抓到就直接显示那 44 个字符，
              电脑当前目录也会生成 vehicle_identifier.txt。
        - 不想用电脑（安卓/iOS）：用手机抓包 App（iOS：Stream / Proxyman；安卓：Reqable）。
          提醒他：安卓 7 以上系统只信用户证书、极氪 App 大概率不认，需要 LSPosed 之类，
          折腾程度高于用电脑，让他自己选。
        - 已经抓到过、手里有 .har 或 jsonl 文件：直接用
              python tools/extract_identifier.py 文件名
          最后一行会输出 IDENTIFIER=...。
第 3 步：等他反馈"抓到了"或"卡住了"。卡住就按下面的排错表逐个排查，一次只查一条。
第 4 步：他把抓包内容粘贴给你（一整段 JSON / HAR / 日志都行，或者截图里的文本）时，你来
        解析：优先找请求头名 x-vehicle-identifier 对应的值；找不到再找所有符合
        ^[A-Za-z0-9+/]{43}=$ 的 44 字符 base64 串；把候选去重后列出来，并说明每个候选
        命中了几次。如果只有一个候选，直接给出结论并让我填进 Home Assistant。
        如果有多个，让我核对：那条请求的响应里 vin 是不是我的车。
第 5 步：给出最终答复，格式固定为：
        车辆标识：<44 个字符>
        依据：<命中方式，比如"在你的 HAR 第 37 条请求头里，命中 1 次">
        下一步：填进 Home Assistant 集成向导的输入框 → 提交。

【排错表】
- 手机打不开 :8081 → 代理没生效/不在同一 WiFi；关掉手机上的 VPN 和私人中继。
- 页面能开但一直等待中 → 证书没信任，HTTPS 没解出来；去系统设置里信任证书。
- 一堆请求但没有 geely 的 → App 用的是缓存界面；在 App 里下拉刷新、切一次车辆页、
  或者开关一次空调再取消。
- 找到头但值是乱码 → 同上，先信任证书。
- 填进去报 00A06 → 抄错车了（多车账号常见），或者复制时截断了；重新核对哪条请求的
  响应 vin 对得上。
- 报 00A17 / 令牌失效 → 这是账号被顶号，不是标识值的问题；告诉他用备用账号或车辆分享，
  然后在 Home Assistant 里走重新认证。

【风格】
- 说人话，中文，不要一次抛一堆术语。
- 每一步都给"做完应该看到什么"，让他自己确认，再进入下一步。
- 不要让我复制执行任何我没要求的脚本，也不要编造不存在的接口。

现在开始第 1 步。
```

---

## 三、为什么这样设计

- **AI 只当向导**：真正需要"算"的地方（认头名、验 44 字符 base64、去重）都是确定性的，
  脚本 `tools/extract_identifier.py` 已经做了；提示词让 AI 在用户不便跑脚本时兜底。
- **不碰凭据**：抓包和解析全程不需要账号密码或验证码，AI 要这些一定是错的。
- **一次只走一条路线**：绝大多数失败是"同时给了三种方法，用户混着做"。
- **红线放在最前面**：退登极氪 App 会把 Home Assistant 顶下线，这是本项目最容易踩的坑
  （见 `docs/获取车辆标识.md` 开头的账号建议）。
