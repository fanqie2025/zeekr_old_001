# 怎么拿到本车的 `x-vehicle-identifier`

> 一句话：这个值 App 只在内存里现算，手机上不存、服务器不下发，**只能从一次真实请求里抄一次**；抄到之后永久有效，跟着车走、不跟账号。

- 形态：44 个 base64 字符，一定以 `=` 结尾，例如
  `GNxEVYPZ7RjM1IPT1vqgC84gsNerq13jzTPXgfEX5Gg=`
- 它出现在发往 `gric-zhf-api.geely.com` / `gric-api.geely.com` 的请求头里，头名就是 `x-vehicle-identifier`。
- 填错不会静默失败：集成会当场报 `00A06 Decrypt X-VEHICLE-IDENTIFIER failed.`，说明值不是这辆车的密文。

## 先看这条：用一个不常用的账号

极氪同一个账号**同一时间只认一处登录**。Home Assistant 一旦和手机 App 用同一个账号，手机 App 重新登录、退出登录、甚至某些版本的前台刷票，都会把 HA 的令牌顶掉，HA 就报 `00A17 The account is currently logged in elsewhere.`。

推荐做法（按省心程度排序）：

1. **把车「分享」给一个备用账号**（极氪 App → 我的 → 车辆分享 / 授权用车），HA 用备用账号登录。主账号在手机上怎么折腾都不影响 HA。
2. 用一张不常用的手机号注册的小号来跑 HA。
3. 实在只有一个账号：手机 App 登出后不要再用那个账号登录，否则 HA 需要重认证。

抓包本身用哪个账号都行，标识值不跟账号走。

## 方法 A：一键助手（Windows / macOS，最省事）

需要电脑装 Python 3.9+ 和 mitmproxy：

```bash
pip install mitmproxy
python tools/catch_identifier.py
```

脚本会打印本机局域网地址，然后：

1. 手机连**同一个 WiFi**
2. 手机 WiFi 设置 → 配置代理 → 手动：服务器填脚本打印的 IP，端口 `8080`
3. 手机浏览器打开 `http://<那个IP>:8081` —— 能看到「等待中」就说明代理通了
4. 手机浏览器打开 `http://<IP>:8080` 装根证书，然后**去系统设置里信任它**
   （iOS：设置 → 通用 → 关于本机 → 证书信任设置 → 打开 mitmproxy）
5. 打开极氪 App，进「爱车」页面，下拉刷新一下
6. 回到 `http://<IP>:8081` 刷新，页面上会直接显示那 44 个字符；同时电脑当前目录会生成 `vehicle_identifier.txt`

抓到后把手机代理关掉，证书可以留着（不影响日常使用）。

## 方法 B：手机端抓包 App（不用电脑）

| 平台 | 工具 | 备注 |
|---|---|---|
| iOS | Stream、Proxyman、Thor | 装描述文件 → 设置里信任证书 |
| Android | Reqable、HttpCanary | Android 7 起系统只信用户证书，极氪 App 很可能不认，需要 LSPosed + JustTrustMe 之类；这步比较折腾，建议优先用方法 A |

步骤都一样：开抓包 → 打开极氪 App 进一次爱车页 → 在抓包结果里搜 `x-vehicle-identifier` → 复制它后面的 44 个字符。

## 方法 C：已经有抓包文件了

手机/浏览器导出 `.har`，或者 mitmproxy 的 jsonl、日志文本，都可以直接喂给脚本：

```bash
python tools/extract_identifier.py capture.har
type log.txt | python tools/extract_identifier.py -
```

脚本会优先按结构化方式找头名，找不到再退化成「44 字符 base64」形态匹配；最后一行固定输出 `IDENTIFIER=...`，方便复制。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机打不开 `:8081` 那个页面 | 代理没生效 / 不在同一 WiFi | 检查 IP 和端口，关掉手机上的 VPN、私人中继 |
| 页面打得开，但一直「等待中」 | 证书没信任，HTTPS 没解出来 | 按方法 A 第 4 步去系统设置信任证书 |
| 抓到一堆请求，就没有 geely 的 | App 用的是缓存的界面，没发真实请求 | 在 App 里下拉刷新、切一次车辆页、开关一次空调再取消 |
| 找到了头，但值是乱码 | 抓包工具没解密（显示的是密文流） | 同上，先信任证书 |
| 填进去报 `00A06` | 抄的不是本车的值（多车账号抄错了） | 抓包时确认那条请求的响应里 `vin` 是你的车 |

## 为什么不能自动算出来

我们验证过：这个值是 App 用**原生库里的密钥**做的 AES-CBC（VIN 补齐后 32 字节），密钥运行时才装配，不在配置里、不在日志里、不下发。离线试过 7056 种密钥/补位/模式/IV 组合，全部不匹配；把两轮完整抓包的**所有响应体**扫了一遍，44 字符 base64 字段出现 **0 次**。

真要做到零手工，只有两条路：从 App 安装包里逆向出那把密钥（有分发与合规风险），或改走 SNC 通道的 `X-VIN`（实测被网关以 `079001 [SDK]此接口未被授权` 拒绝）。所以发布版保留这一步人工填写，但只填一次。
